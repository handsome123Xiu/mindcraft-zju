# Mindcraft：任务计划与按需代码补充

> 历史文档：下文描述此前的通用 Agent。当前 `main.js` 已切换为建筑专用入口，不再按此流程运行。请使用 [建筑版说明](../BUILDING.md) 中的配置和指令；保留旧模块源码不代表默认启用了这些能力。

此前实验使用课程 API 的 `gpt-6-sol`；发布版需自行配置模型与接口。模型在远程生成计划和 JavaScript；脚本由本机 Node.js 执行，通过 Mineflayer 控制游戏。这不是在电脑上部署了本地大模型，也不是完整的 Voyager。

## 怎样使用

照常运行 `Start-Mindcraft.cmd`，输入当前世界“对局域网开放”的端口，然后在 Minecraft 聊天里给 Andy 一个目标。例如：

> 帮我准备一把石镐并带回来。先列出材料和制作计划，缺少材料就获取，完成后到 bottle 身边。

第一条消息会多一次计划模型调用，响应可能比原先慢。Andy 先读背包、位置、玩家信息，列出最多 12 步及依赖、前提和完成条件，然后自动逐步执行。关键目标不明确时会询问；普通细节可采用模型说明的默认值。

| 聊天指令 | 作用 |
|---|---|
| `!plan` | 查看计划、当前步骤和阻塞原因，不需要模型调用 |
| `!pausePlan` 或 `暂停` | 暂停计划，打断当前动作和旧模型回复 |
| `!resumePlan` 或 `继续任务` | 继续已有计划，重置本轮决策限额 |
| `!cancelPlan` 或 `取消任务` | 取消计划 |
| 直接发送修改后的任务 | 根据当前状态生成替代计划，旧计划归档 |

不要同时启动旧的 `!goal` 自我提示循环；启用计划时它会被拦截。重启后未完成计划会保留但暂停，需要检查世界是否相同，再继续。

## 完成判定与代码补充

背包物品数量、到达坐标、接近指定玩家、某坐标方块类型由程序读取游戏状态判断。建造品质、复杂交互等暂时不能自动验证的结果，会记录为 `model_reported`（模型提供证据），不能当成程序验证过的成功。前提条件目前主要由模型检查，并非完整形式化规划器。

默认使用现成技能或技能组合。若无法表达当前步骤，规划器可标记 `execution: code` 并写明缺少的能力；执行过程中也可通过 `!requestCode` 提出原因，再用 `!newAction`。缺材料、名字错误或一次寻路失败本身不是转代码的理由。这是提示词和基本参数校验约束，能力缺口仍由模型判断。

脚本先检查语法及已知技能名，再在本机执行；错误最多进行 3 轮生成/修正。每次代码动作设置 2 分钟协作式超时（包含生成过程），并插入循环/函数入口检查；每轮计划最多 40 次调度决策，连续 3 次匹配到的指令失败或 3 次无指令响应会暂停。这些限制不是严格的 API 费用上限，单轮可能还包含模型重试、记忆压缩等请求。

代码仍能操作暴露的 bot 对象和游戏世界。SES 与检查器不是独立操作系统沙箱，不能保证拦截所有卡死或越界代码。底层 Mineflayer 寻路、合成、放置问题也不会因加计划而自动消失。先在测试世界试复杂任务。

## 研究记录在哪里

- 当前计划：`bots\andy\task-plan.json`
- 原始计划提案及旧计划：`bots\andy\plans\`
- 通过检查的执行脚本：`bots\andy\action-code\`
- 生成代码、触发原因与执行结果：上述目录的 `executions.jsonl`（含未通过检查的代码）
- 模型 token 及请求耗时：`logs/api-usage.jsonl`
- 原实验目录与历史备份不包含在发布包中。

代码只留档，不会自动被训练、检索成 Voyager 那样的长期技能库。

## 开关与回归测试

`mindcraft\settings.js` 的 `explicit_task_planning` 与 `allow_insecure_coding` 当前均为 `true`；均设为 `false` 后重启可回到普通对话技能模式。要让旧自我提示机制工作，请关闭规划开关。修改磁盘设置后需重启主程序，已有 MindServer 的内存设置不会自动刷新。

在 仓库根目录 中运行：

```powershell
npm test
```

测试不调用收费模型，也不修改 Minecraft 世界，覆盖计划依赖、状态校验、恢复、停止与并发消息、API 错误恢复、脚本语法检查和循环限额。
