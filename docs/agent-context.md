# 建筑 Agent 上下文和决策协议

决策使用“当前状态 + 持久任务约束 + 按需工具信息”。完整几何留在共享蓝图，最近工具结果生成确定性摘要，不额外调用模型做摘要。

观察范围及是否再次观察由模型根据任务选择。启动和恢复时不自动调用 observe_environment；已有观察保留范围、坐标、结果、维度及 observedAt。移动、方块操作、等待后继续或跨进程恢复只将 freshness 标为 possibly_stale 并记录 staleReasons；该标记表示不确定，不强制重新扫描。模型结合任务、当前位置和已有信息决定复用、局部补查或扩大区域。inspect_block 结果独立保存到最近 16 个位置的 blockObservations，主循环和设计 skill 都能读取；单格复查不会把整个区域标记为新鲜。旧状态的未知时间保留为 null。

设计仍需整体计划，但不再检查“必须有 job.observation”；模型判断现有证据是否足够。蓝图发布前的全量现场冲突检查和最终验收继续执行。恢复时旧整体验收缓存清空，施工清单重新读取现场。observe_environment 的 region.min/max 仍是必填世界坐标；JSON 与原生函数共用 schema，省略时返回参数错误。每轴 256 格、体积 2000000 格、距任务原点 256 格是执行边界，不用于替模型选尺寸。纯聊天无需扫描。

- 原始目标、需求、当前计划、蓝图版本、施工范围、剩余清单和用户补充要求始终可见。用户补充要求独立持久化，不随最近 40 条聊天滚动丢失；旧状态从仍可用的用户事件迁移。
- 最近四项工具反馈保留状态和错误，合并连续重复反馈，压缩大量差异坐标；最新 `inspect_part` 的可执行建议保留。原始响应文件和状态中的事件不受模型视图压缩影响。
- 当前世界快照只提供一份；观测保留扫描范围、完整计数、未加载位置、有限样本及真实分页入口。样本省略不代表空气。
- 蓝图几何通过 `inspect_blueprint` 查询，材料通过 `list_materials` 查询；`get_tool_help` 返回完整说明和参数 schema。常用工具与最新施工建议立即提供，其余工具获取帮助后进入当前函数协议。
- lead 看到任务和未派单范围统计；builder 只收到自己的责任范围和相应动作能力。未派单数量是任务覆盖统计，不是现场完成证明。分工由 agent 决定，系统不自动左右切分或派单。

## DeepSeek

决策请求直接提供 `update_plan`、`delegate_task`、`inspect_part` 等独立原生函数。没有 `submit_action`、`tool` 或 `batch` 元函数；参数不需要再嵌套 action/name/args。函数参数与本地校验来自同一份 schema。

DeepSeek 当前不支持在 thinking 模式强制指定函数，因此决策请求使用 `reasoning.effort=none`；蓝图 skill 仍使用 profile 配置的推理强度。蓝图的固定 skill 说明与动态任务输入分开，去掉重复的几何动作指南。

CORE 指令自 2026-11-15 起以具体 JSON 示例教学协议：单动作 `{"action":"tool",...}`、多步合并为单个 batch、明确禁止把动作名作顶层键（多键信封/追加第二个 JSON 对象都无效）；建造顺序（评估→update_plan→design_blueprint→施工→验收）前置到第二行。背景：真实日志中 52/84 个 run 的首个反馈是错误，多键信封（模型想一次做多件事）与顺序颠倒（跳过 plan 直接 design）是最大两类协议性浪费。

正式启动统一使用 `createLazyBuildingModel`，在延迟初始化时也暴露决策协议。指令、错误恢复和 API 函数通道一致，避免发送旧 JSON/batch 指令却只接受原生函数。常用检查、移动与施工函数始终可用，其余函数按帮助发现。`get_tool_help` 也支持设计 skill。新增计划步骤使用完整 steps（解析期即校验 title/success），patch 按 id 合并更新并按顺序追加新 id；update_plan 语义错误按 INVALID_PLAN 计入连续失败计数。

上下文是视图层确定性裁剪，不改动持久状态：团队生命周期事件进 `teamFeed`（12 条、160 字符、带 kind）而不是聊天窗口；任务列表为紧凑视图（长文本 80/100/120 截断、scope 摘要、无凭据），完整记录靠 `list_tasks`；`get_build_checklist`/`inspect_build` 事件只留计数；JSON 模式指令仅给 focus 工具完整 schema，其余列名指向 `get_tool_help`。真实最坏运行样本实测：recentEvents -67%、team section -53%，新任务的聊天窗口不再被事件灌满（估算整体 -65% 以上）。

DeepSeek 蓝图请求至少保留 8192 个输出 token。明确因输出预算截断时，仅自动重试一次，关闭该次推理以保留 JSON 输出空间；不改变 profile 或原始要求。两次仍失败交由外层进度保护处理。

新蓝图发布前检查完整目标及显式空位，遇到已有方块冲突或未加载格拒绝发布并返回样本，避免对子 agent 隐式授权拆除旧建筑。新编译蓝图只将 shape 内部和 opening 声明为空位；独立建筑之间的间隔不默认清理。旧保存蓝图保留原验收契约，不静默改写。

`inspect_part` 对目标材料错误的占位提供基于实测材料的 dig 建议，拆除后重新观察再放置；写权限、租约和目标变化检查继续生效。实体挡住放置时反馈具体阻挡者及位置。子任务因协议、网络或无进展自动停止时报告 blocked，释放租约供 lead 重派；用户/全队显式暂停仍保留可恢复的任务。

原生调用不是本地校验的替代品：依旧验证名称、全部参数、角色、租约、精确坐标及最终蓝图。一轮可以包含多个工具调用和计划更新，适配器按返回顺序转换为内部批次。整批参数和计划语义先校验，再执行；遇到运行时阻塞停止后续步骤。协调回合不能通过批次修改计划。设计、等待和完成函数必须单独调用，先读取前一轮操作结果。DSML 文本和缺少函数名的裸参数不会被猜测执行。失败的原生参数也保留到响应日志，并反馈具体字段错误。

日志 `logs/api-usage.jsonl` 记录实际 token、请求协议、系统说明长度及各上下文区块长度；不记录 key 或完整提示词。任务模型输出仍写入各 run 的 `response-*.json`。

## 验证与诊断

`npm test` 包含上下文、原生调用、范围交集、批次预检、角色、持久用户要求及三进程协作回归。

`test-agent-regressions.mjs` 覆盖正式启动封装→循环→Responses 适配器（模拟 HTTP）、预算重试、占位发布拒绝和停止状态传播。三进程夹具也使用正式启动封装与原生函数校验，并通过施工屏障及实际操作时间验证两名 builder 同时施工；模型与 Minecraft 世界均为测试替身，不代表真实游戏已完成复测。

```powershell
# 仅统计保存状态的上下文
node scripts/replay-decision.mjs bots/lead/builds/<run-id>.state.json

# 调用真实 API，但只解析建议，不执行任何游戏工具
node scripts/replay-decision.mjs bots/lead/builds/<run-id>.state.json --probe

# 真实模型 + 内存任务运行时 + 合成平地，验证至少两个 builder 可同时领任务
node scripts/probe-team-dispatch.mjs bots/lead/builds/<run-id>.state.json --probe
```

重放不会连接 Minecraft 或改写原工程；模拟地形只用于诊断，不能证明真实现场的可达性或建筑质量。任务仍须通过真实世界的部件与全局验收。

重载时停止团队并重新启动控制台、团队。活动工程在运行时和 leader 两处均恢复为暂停状态，builder 不会提前领取旧队列，原蓝图保留；确认原方案可继续时向 lead 发送“继续建造”。已有选址错误的工程应取消后重建，不会静默迁移旧蓝图或拆除已有建筑。

团队主 agent 最终 blocked 或自动暂停时，工程结算为 failed，撤销剩余任务、租约和待处理协作提案，通知子 agent 停止；下一条用户任务会创建新工程。子 agent 局部失败仍报告 lead 重派。用户显式暂停、等待用户和等待团队不结束工程。启动时自动归档旧版本遗留的失败状态，避免已失败工程继续锁定成员和连线。

协调者自身空转不代表工程失败：存在 running 子任务，或依赖已满足、执行者在线且 canAcceptTask=true、未标记 claimStalled 的 queued 子任务时，连续三轮无进展自动转为 waiting_team，停止调用模型，保留子任务写租约。本轮请求数/时间预算耗尽也先检查子任务并转为等待。子任务领取、完成、阻塞和重新排队事件唤醒协调者；等待状态保存期间到达的事件不会丢失。所有待办均因失败依赖阻塞时不进入无限等待，明确失败与用户取消仍走工程收尾。

team.agents 额外提供 online、status、canAcceptTask；未知就绪状态不能当作可接单。队友交流回合因预算、协议或无进展自动暂停时转为 blocked，释放本地接单门槛；用户/团队明确暂停仍需恢复。交流回合不获得施工权限。任务在工程运行且依赖满足后超过 15 秒仍未领取，运行时标记 claimStalled，并对本次派单发送一次 task_unclaimed 通知；重派后重新计时，暂停工程和等待依赖不计时。leader 使用原 taskId 调用 reassign_task，目标可以是原成员或其他可接单成员；重复委托冲突会返回原任务 ID 与恢复方法。显式 wait_for_team 也检查可执行工作，避免在线但暂停的成员导致无限等待。

画布“保存并开始新测试”发送 fresh=true，归档未结束工程后使用当前结构启动，保留历史日志与世界方块；“恢复旧工程”保留原任务及结构校验。两者均先停止正在运行的团队。测试覆盖失败后直接提交新任务、写租约失效、取消回执、旧状态迁移以及替换整个团队入口。
