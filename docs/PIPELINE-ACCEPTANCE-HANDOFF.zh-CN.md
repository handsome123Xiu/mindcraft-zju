# Pipeline：末段施工向验收交接（2026-11-23）

## 用户要求与结果

删除 Designer 与 Acceptor 之间的直接连线。默认画布现在只有：

`Designer → Builder → Acceptor`

多 Builder 时，保留设计者向各施工成员派工的连线、相邻施工段的交接连线，以及末段到验收成员的连线。

Designer 只登记施工任务。末段 Builder 现场自检并成功 complete_task 后，运行时正式创建全场验收任务，from 为该 Builder，to 为 Acceptor；不需要 Designer 再放行、派发或确认。

## 共享系统层改动

新增可选成员配置 `taskAcceptanceTo`，当前仅 Pipeline 末段配置。目标必须有实际连线、持有 finishGate，且没有设计、放置或拆除权限。未配置的成员沿用原流程，没有按范式名或成员名写死调度。

完成结果与验收任务创建在同一 SQLite 事务内结算。验收任务覆盖当前蓝图全部部件和预留空位，依赖当前版本的全部有效施工任务；它是独立验收任务，不是末段的子任务，不缩减或转移施工 scope。重复完成结果不会重复创建验收任务。blocked 不会触发交接。

只读验收成员可以直接领取任务，不再需要借用 delegate_task 权限取得领取资格。验收成员仍不能放置或拆除。

验收发现差异时，先沿连线向末段 Builder 报告，再 blocked；由末段转达 Designer。被阻塞的只读验收范围不阻止 Designer 登记明确的返工施工任务。末段成员可在协调回合重派自己交出的原验收任务；运行时会重新登记返工依赖，返工完成前验收者无法领取。

当前画布、预设、前端序列化、旧页面保存兼容与恢复时的结构核对，均包含新字段。普通任务、通信连线检查和施工租约仍按原有规则执行。

原 design_blueprint、蓝图发布校验、CORE、Agent 主循环和 finish 的验收条件均未修改；个人 API 与模型 Profile 文件未修改。
