# 平等协商阻塞恢复改进（2026-11-22）

## 本轮现象

工程 本地验证记录 的蓝图共 3633 格，实际完成 729 格。底座上层施工遇到 unreachable / server_correction；中层任务未登记底座依赖，提前领取后遇到 missing_reference。成员反复互相确认，18 个协调回合消耗 134 次模型请求；其中 16 次把 send_message 和 end_turn 放在同一原生响应，整组被协议拒绝。

## Profile 修改

仅更新平等协商预设：明确协商收敛、没有新事实不回复确认；以实际 taskId 登记支撑和先后依赖；正式任务恢复必须由委托者重派，不能靠聊天改变状态；独立调用结束动作。没有在系统中写死成员顺序、建筑类型或尺寸。

## 共享系统层修改（需上报）

- loop-agent.js：存在 blocked 任务时仍识别其他 running 或确实可领取的工作；重复查询后等待团队事件，保留全部任务。全部无法推进时记录带 teamRecovery 标记的等待；只在真实任务状态变化时重新唤醒，聊天确认和租约续期不算变化。普通用户问题与显式暂停不受这种唤醒影响。
- team-runtime.js：正式 reassign 补发 task_reassigned 生命周期事件，沿用原有的报告接收者和连线约束。
- decision-context.js / native-actions.js：加强协调回合和原生工具描述，明确“发消息、读取结果、下一次响应单独 end_turn”。动作协议的拒绝规则保持不变。
- flight-actions.js：区分正常路径与实际穿墙脱困路径。开启 passThroughWalls 时，正常无碰撞路线仍逐步检查动态障碍，遇到新障碍停止并恢复物理状态。既有脱困选项和服务端纠正后的停止行为保留；不会把服务端拒绝当成成功。

未修改原始 design_blueprint、蓝图发布校验、施工权限与租约、finish 验收函数、CORE 通用底稿或 API 配置。

## 验证与使用

真实 loop/client/runtime 的离线回归同时覆盖中心化、平等协商：并行工作保留、阻塞依赖、重派事件唤醒、确认消息不唤醒、手动暂停、预算和最终验收。移动回归覆盖动态障碍及服务端纠正恢复。另运行完整团队、黑板、上下文和 DeepSeek 原生协议测试。

需要重启控制台和团队进程加载系统代码。已保存画布和旧工程的 Profile 是快照，不会因修改预设自动升级；新测试请重新应用“平等协商”预设。旧工程缺失的 dependsOn 也不会自动补写。本轮保留旧工程和已建方块，没有静默恢复施工或重新生成蓝图。

真实 Minecraft 验证需要可连接的局域网世界。本轮未能连接测试世界；离线移动测试通过不能证明原世界的 server_correction 已完全解除。
